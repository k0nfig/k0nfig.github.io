Event-driven workflows / PowerSchool

From manual step to automated invitation

A midnight schedule, a duplicate-send check, and a deliberate daily recovery cadence.

The manual step

Inviting users who did not yet have accounts was a manual process at PowerSchool. Automating that step was the focus of this project.

What I built

I built a distributed, asynchronous account invitation workflow using AWS serverless services and Auth0. My contribution covered the workflow that replaced the manual invitation process.

The daily run

An EventBridge schedule triggered the system at midnight for customers. Scheduling gave the invitation process a regular daily starting point.

  1. 01 / Trigger

    Start at midnight

    The EventBridge schedule started the invitation workflow.

  2. 02 / Check

    Check for a previous send

    Before sending an email, the responsible Lambda checked whether an email had already been sent. This check prevented duplicate invitations.

  3. 03 / Act

    Send or skip

    The sender skipped emails that had already been sent and sent the remaining invitations.

Failures and the daily recovery cadence

Failures were logged and generated alerts. We chose to rely on the next day’s scheduled run for another attempt, rather than introducing a dedicated retry queue.

Why a daily run was enough

Waiting for the next scheduled run was sufficient for this use case. We accepted that delay and kept recovery aligned with the daily cadence. The previous-send check prevented an already-sent email from being duplicated on subsequent runs.
